### Finding TAFI-GAP-011 — Solo playoff bracket contradicts the stored playoff games
- Class: bug · Suggested severity: **High** · Mode: SP (adapter path) · Screen/system: `HybridSimulationService.simulatePlayoffRound`, `server/index.ts` `playoffRound`, `/bracket`, Game History
- Grounding: controlled-sim (headless, real engine) + played-in-UI (one observed instance)
- Observed: seed 4001, engine, every checked season (2027–2030) has bracket matchups with **no stored game** and stored games between teams the bracket says were eliminated. 2027: bracket AFC DIV = LAC–HOU and NYJ–CIN (winners never set), CONF = KC–CLE (never set); stored games: DIV LAC–CLE 17-21 and HOU–KC 16-36, CONF LAC–HOU 29-16; the bracket champion (LAC) still came from the SB game. 2029: 7 of 13 matchups unmatched. In the UI run (seed 47547, 2027) the human's WC box score is **BAL 28–31 NYJ (a loss)** yet BAL went on to a DIV win and won the Super Bowl; history records `furthestRound: WC` with `wonSuperBowl: true`.
- Expected: one set of playoff results; every bracket matchup has the game that decided it, and every game is a bracket matchup.
- Repro: `harness/bracket_check_snippet.txt` in the 2-season engine harness (adapter up); or play the 2027 playoffs by UI and compare `/bracket` with Game History. Reproducibility: always in headless (4/4 seasons); once observed by eye in UI (the playoff games of other teams are not shown in UI, so a human sees it only through their own box scores).
- Evidence: `evidence/playoff-bracket-vs-games-seed4001-2027.json`, `playoff-bracket-vs-games-findings.txt`.
- Root cause: **mechanism confirmed, trigger suspected.** The adapter is a stateless stepper: each `/playoffs/round` call replays every earlier round from the seed (`server/index.ts` ~192–310) and the UI then merges the returned games by matching `highSeed/lowSeed` to its own matchups. Unmatched games are still appended to history. If any input to the replay changes between calls (rosters/injuries after each round, depth charts), the replayed earlier rounds produce different winners than the ones the UI already recorded. Not yet proven which input differs.
- Proposed solution: send the already-decided results (winners/scores) with each call so the adapter **applies** earlier rounds instead of re-simulating them; make the UI reject/flag a returned game that matches no matchup. Alternative: store the seeded bracket progress client-side (as `startPlayoffs → playPlayoffRound` in `season.ts` already does in the TS runtime) and use that module directly.
- Difficulty: M. Benefit: playoff history, awards and "who beat whom" become trustworthy.
- Related: #74 (any engine-in-browser would use `playPlayoffRound` directly and avoid the replay; but only if it keeps the progress state), GAP-005.
- Regression check: after each round, assert `∀ matchup ∃ game` and `∀ game ∈ matchups`, winners equal; run over ≥ 20 seeded seasons.
- Uncertainty: online (nfl format) playoff path not tested (my live league was 4 teams → only a final).
